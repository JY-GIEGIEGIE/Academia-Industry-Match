# 产学研对接前端

前端基于 Vue 3、TypeScript 和 Vite，已完成 S-14 第二轮冲刺闭环页面，覆盖双角色登录、成果与需求发布、异步匹配任务状态轮询、双端推荐与匹配详情、合作意向表达、确认和拒绝，以及双方确认后的演示联系方式披露。默认通过 HTTP 接入 S-11 后端，也支持使用本地 Mock 离线演示。

## 从仓库启动

需要 Node.js 20.19 及以上的 20.x 版本，或 22.12 及以上版本。以下启动命令从包含 `AGENTS.md`、`docs/` 和 `frontend/` 的仓库根目录执行。启动后打开 `http://127.0.0.1:5173/`。如果端口已被占用，Vite 会直接报错。

### 真实后端联调（默认 HTTP 模式）

1. 按 S-12 说明初始化并启动 PostgreSQL 开发库 `s2_mvp_20261125` 和 Redis，用 `scripts/dev/seed_demo.py` 初始化科研端与企业端演示账号。仓库默认的 `docker compose up -d db redis` 启动数据库和 Redis。详见 [S-12 开发库与部署说明](../docs/09-项目管理/开发库与部署说明_2026-11-25.md)。
2. 启动 S-11 FastAPI，使其监听 `http://127.0.0.1:8000`，并启动处理匹配任务的 Celery worker。API 与 worker 使用同一 S-12 开发库和 Redis。
3. 启动前端，用 `research_demo` 或 `enterprise_demo` 和 S-12 初始化脚本为演示账号设置的密码登录。

```sh
cd frontend && npm ci && npm run dev
```

浏览器默认请求 `/api/v1`，由 Vite 将 `/api` 请求代理到 `http://127.0.0.1:8000`。如需调整，在 `frontend/.env.local` 中设置 `VITE_API_BASE_URL`（默认 `/api/v1`，也可设为带该前缀的完整 API URL）或 `VITE_API_PROXY_TARGET`（Vite 开发代理的上游地址）。变量见 [环境变量示例](.env.example)。

#### 生产构建与 Nginx 部署

在 `frontend/` 安装依赖后运行 `npm run build`，产物位于 `frontend/dist/`。部署时由 Nginx 静态托管该目录，并将 `/api` 反向代理到 `http://api:8000`，保留原始请求路径（例如 `/api/v1/...`）。前端构建使用默认的 `/api/v1` 作为同源 API 前缀。可运行 `npm run preview` 本地预览静态构建产物。

### 本地离线模拟（Mock 模式）

Mock 使用仓库自带样例，无需后端或数据库。首次安装依赖后即可离线启动。

```sh
cd frontend && npm ci && npm run dev:mock
```

用 `research_demo`（科研端）或 `enterprise_demo`（企业端）登录，输入任意非空密码即可演示。Mock 的发布、匹配任务和意向保存在当前标签页的会话中。演示双方对同一条意向的操作时，请在同一标签页退出并换账号登录。

在 Windows 上，如果 `dev:mock` 提示无法识别 `VITE_API_MODE`，在 PowerShell 的 `frontend/` 目录运行下列命令启动 Mock。

```powershell
$env:VITE_API_MODE = 'mock'
npm run dev
```

结束演示后，在同一 PowerShell 中运行 `Remove-Item Env:VITE_API_MODE` 恢复默认 HTTP 模式。

### Windows 安装时提示 EPERM、无法删除 esbuild.exe

这通常表示前端开发或预览服务仍在占用该文件。`npm ci` 会先清理现有 `node_modules`，而 Windows 不允许删除正在运行的程序，因此导致清理失败。

请先在运行本项目 `npm run dev`、`npm run preview` 或持续测试的终端按 `Ctrl+C` 停止服务，再在 `frontend` 目录重新运行 `npm ci`，安装成功后再运行 `npm run dev`。日常已安装依赖时直接执行 `npm run dev` 即可，无需每次 `npm ci`。若仍出现相同错误，请先确认本项目相关进程已退出，再进一步检查文件权限或其他占用来源。

## 完整闭环演示（S-14 验收路径）

真实联调使用 S-12 开发库里可发布的演示成果和需求，选择能形成同一配对的记录。Mock 可用成果 `Application of Solid Electrolytes in Solid-State Lithium-Ion Batteries`（`ach_openalex_W7127158161`）和需求“硫化物固态电解质中试放大”（`dem_005`）。

顶栏显示当前账号和角色。科研账号可发布成果并查看适配的企业需求，企业账号可发布需求并查看推荐的科研成果。推荐链接里的 `view` 由登录身份决定。可退出再登录另一个账号，也可独立打开两个标签页分别登录。HTTP 模式下两个标签页通过后端共享发布和意向记录。

1. 用 `research_demo` 登录，进入“发布成果”，在数据池中选一条未发布的成果，点击“确认发布并触发匹配”。页面自动轮询任务状态。看到“匹配已完成”后，点击“前往查看推荐结果”，打开一条配对详情。若部分精排回退，页面会提示基础匹配已完成。若轮询暂停，可点“手动刷新状态”。
2. 用 `enterprise_demo` 登录，进入“发布需求”，选择同一配对的需求并点击“确认发布并触发匹配”。等待轮询完成，进入推荐并打开该配对。用成果与需求 ID 对照两端的同一配对，核对双方资料、推荐理由、指标、风险和证据一致。
3. 双方发布后，任一方在配对详情点击“表达合作意向”。用另一方账号打开同一详情页，点击“确认合作意向”或“拒绝意向”。也可在“合作意向”页找到标为“待我方确认”的记录，点击“确认合作”或“拒绝”。
4. 确认后，用双方账号查看标注“演示联系方式（非真实联系人）”的科研方和企业方联系人。验证拒绝分支时，用另一组双方已发布的配对发出并拒绝意向，核对状态和联系方式披露情况。

### 空值与降级展示

| 数据或状态         | 页面展示                            |
| ------------------ | ----------------------------------- |
| `trl=null`         | 待评估                              |
| 应用场景为空       | 待确认/未知                         |
| `needs_review`     | 待审核/待复核（发布页显示“待复核”） |

## 数据说明

- 本轮共20条唯一演示配对，由4篇真实OpenAlex论文和5条模拟需求组成，聚焦电解质方向；每个演示对象只会展示与它关联的配对。
- 样例来自S-02 v0.1组内交接；这里的“S-02”只是来源版本名称，并不是要求大家保留的文件夹名称。全库包含300篇成果、100条需求和25家企业，本轮只提供前端需要的受限样例。
- 企业和需求均为模拟资料，企业只使用化名；样例中不包含作者、机构、企业真实名称或联系人。
- 摘要样例最多保留600字符，列表预览最多300字符；完整摘要不会放进公开仓库。
- 中文说明由Codex根据标题整理并标明了机器生成；演示分类依据标题和采集类别整理，不作为正式抽取结果。
- 本轮 fixtures 是演示快照：能力画像是短说明，不是 150—250 字正式画像；`trl=null`、`review_status=pending` 等字段保留演示状态，不作为正式数据契约验收依据。前端正式接入真实数据时，再按 `data/spec/data_contract_v0.1.md` 校验。
- 成熟度没有依据时显示“待评估”，知识产权情况不明时显示“未知”，性能指标保持“尚未核实”。
- 分数、理由和风险都是固定演示资料，没有运行真实匹配、精排或向量模型，适配度也不代表成交概率。
- 样例中包含1条未精排和3条失效配对；风险等级1最低、5最高，未精排显示“待精排/评估”，失效显示“待重算”。

## 可选：重新生成演示样例

日常安装、启动、测试和构建都会直接使用仓库里的 `src/mock/fixtures.json`，不需要执行这一节。

只有负责重新整理样例的组员，才需要从组内另行获取并解压数据交接包。数据目录放在哪里、叫什么都可以，执行时把下面命令里的占位文字替换成实际目录即可：

```sh
node src/mock/build-mock-data.mjs --source "<解压后数据交接目录>"
```

这条命令从 `frontend/` 目录执行。`--source` 既可以是绝对路径，也可以是相对于当前终端目录的路径，指定目录需要包含以下文件：

```text
data/processed/
  achievements_clean_v0.1.jsonl
  demands_v0.1.jsonl
  enterprises_v0.1.jsonl
```

脚本不会默认去仓库旁找文件夹，如果不传 `--source`，它会显示用法并直接退出。生成结果始终写回脚本旁的 `fixtures.json` 和 `manifest.json`，不会随终端所在目录改变；它也只复制受限字段和截断摘要，私有原始数据不会被搬进仓库。想看参数用法可以运行 `node src/mock/build-mock-data.mjs --help`。

## 验收检查命令

在 `frontend/` 目录运行以下命令检查代码和构建状态：

```sh
npm run build
npm test
npm run lint
npm run format:check
```

`npm test` 覆盖 HTTP 与 Mock 适配、发布和意向流程、任务轮询、推荐路由的角色约束以及意向状态文案。真实联调对齐 S-11 v0.1.2，分页使用 `items/pagination`，企业名读取 `enterprise.display_name`，标签文字来自当前模式的 taxonomy 接口。HTTP 适配器保留任务查询的 HTTP 404，并归一化两种演示联系方式。登录状态存入 `sessionStorage`，刷新后通过 `/auth/me` 恢复。

浏览器验收按上面的完整闭环步骤执行，并单独记录所用模式、配对和操作结果。
