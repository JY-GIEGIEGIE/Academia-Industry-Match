# 路径兼容与共享说明

这份说明位于仓库的 `frontend/` 目录。日常启动步骤见 [README](README.md)，页面设计见 [DESIGN](DESIGN.md)，详细验收记录和截图见 [交付与验收记录](docs/交付与验收记录.md)，这些链接指向的都是仓库内的文件。

## 组员拿到代码后怎么使用

在本地仓库根目录打开终端，运行：

```sh
cd frontend
npm ci
npm run dev
```

仓库放在任意磁盘、改成别的文件夹名称都能正常使用。前端会直接读取仓库里的 `src/mock/fixtures.json`，不需要私有数据交接包，也不用依赖特定磁盘路径或仓库旁的其他文件夹；正常跑测试和打包构建也一样不需要私有交接包。

注意 `http://127.0.0.1:5173/` 始终指向你自己的电脑，需要先在本地启动服务才能访问。源码和本说明尚未推送到远程；等大家拿到本轮代码后，就可以按这个步骤启动。

## 只有重新整理样例时才需要额外资料

只有负责重新生成样例的组员，才需要从组内另行获取并解压数据交接包，然后在 `frontend/` 目录运行：

```sh
node src/mock/build-mock-data.mjs --source "<解压后数据交接目录>"
```

执行时把占位文字替换成实际目录就行。`--source` 可以用绝对路径，也可以用相对于当前终端目录的路径，目录叫什么、放在哪里都没有限制，但里面需要包含 `data/processed/achievements_clean_v0.1.jsonl`、`data/processed/demands_v0.1.jsonl` 和 `data/processed/enterprises_v0.1.jsonl`。

脚本不会默认寻找固定路径或特定机器上的交接目录；没有传 `--source` 时会显示用法并直接退出。输出结果始终写回脚本同级的 `fixtures.json` 和 `manifest.json`，不会随终端当前所在目录改变。

## 本轮路径兼容验证

- 仅提取仓库内可提交的前端文件，放进不同路径，并把副本文件夹重命名为带空格的新名称。
- 干净副本里不带 `node_modules/` 或私有交接包；重新安装依赖后，7项单元测试和生产构建均已通过。
- 重建脚本在查看帮助、缺少 `--source` 参数以及输入目录不存在等情况下，都按预期提示并退出。
- 用仓库内的受限样例构造测试输入，放进任意命名且带空格的数据目录中测试，没有复制完整私有数据。
- 从不同的终端工作目录调用同一个脚本，输出都会回到脚本所在目录，演示数据的SHA-256保持一致；当输入缺失时，已有样例不会被覆盖。

以上就是本轮本地路径兼容验证的情况。页面原本的7项单元测试、11项浏览器检查和共享截图见详细验收记录；本轮路径与文档修改不代表重新做了视觉验收，远程CI也尚未运行。
