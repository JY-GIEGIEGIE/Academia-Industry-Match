## 1. 分配原则

1. **单一主责**：每个任务只有一个主责人；协作人只提供接口、数据或评审，不共同承担交付责任。
2. **角色连续**：每个人一个主任务；PM 按本轮要求额外主责 S-16 训练实验，S-15 与 S-16 同属验收/评估链，不构成同一任务的双主责。
3. **接口先行**：11/26 Kickoff 冻结用户、发布、匹配、意向四组接口和表结构；未冻结前不各写一套。
4. **依赖显式**：只列硬依赖；能用样例、mock、契约并行的，不算阻塞。
5. **Agent 加速但不替代主责**：Agent 可并行生成脚手架、接口测试、页面骨架和文档；主责人必须审查、运行测试并承担交付。
6. **完成定义**：代码/脚本 + 测试 + 文档/证据 + 可演示结果；不以“Agent 已生成”作为完成标准。

## 4. 任务详情

### S-10 发布触发的双向匹配引擎（陈镇灏）

**目标**：发布动作触发真实匹配；同一 pair 同时服务企业和科研两端；P1 补 LLM 精排/理由/风险/证据。

**工作内容**

1. 与 S-11/S-12 冻结匹配/任务契约：`match_id`、输入对象、任务状态、`risk`/`evidence` null 语义。
2. B2：对新发布成果/需求与全量异侧对象做标签过滤 + 向量余弦 + 归一化；生成规则化 `reason`；`risk`/`evidence` 暂空。
3. Celery 任务：实现 `run_match_for_achievement` / `run_match_for_demand`；写 `pipeline_run(stage=match)` 状态；幂等重跑。
4. P1：演示 pair/Top-K 做 LLM 精排，生成 `risk`、`evidence`、自然语言理由；失败回退 B2。
5. 对从数据池选择的演示记录，复用已有标签/画像/向量；本轮发布只绑定现有记录，**不允许改技术文本或新建 ID**；遇到未知对象必须报错，不能 success 0。
6. 交付匹配脚本、任务函数、测试和匹配说明；不修改 v0.1.2 processed，不写验收库。

**交付物**

- `scripts/match/`：B2、任务函数、LLM 精排。
- Celery 任务模块（供 S-12 worker 加载）。
- `docs/09-项目管理/匹配引擎说明_2026-11-25.md`。
- 20 条样例匹配结果（11/27 前给 S-11/S-14 解阻塞）。
- 匹配/任务测试与指标。

**完成标准**

- 发布后能创建匹配任务并产出真实 `match_score`；同一 pair 唯一。
- 企业端/科研端查询同一 pair 得到同一 `match_id` 和分数。
- B2 的 `risk`/`evidence` 为 `null`；P1 精排失败可回退。
- 任务重复执行不产生重复行；状态可查询。
- 不修改 v0.1.2 数据；不写验收库。

**依赖/协作**

- 依赖：v0.1.2 数据/画像/向量已就绪；S-12 的 Celery/Redis 容器。
- 协作：朱柔璇确认任务/结果字段；张小桐确认 worker 加载方式；黄欣悦提供演示 pair。

### S-16 弱监督 reranker 训练实验（贾越，PM）

**目标**：把“训练”做成可复核的实验亮点；不阻塞主链，不拿人工测试集训练。

**工作内容**

5. 若明确正向，可作为 API 可选 reranker；若没有提升，不接入线上路径。
6. 不做 LLM/embedding fine-tune；模型文件不入库，只保留脚本、配置和报告。
