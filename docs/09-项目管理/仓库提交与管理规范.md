# 仓库提交与管理规范

## 1. 分支

- `main` 受保护：不直接 push，不允许 force push 或删除。
- 从最新 `main` 拉短分支：
  - `feat/<area>-<short>`
  - `fix/<area>-<short>`
  - `docs/<short>`
  - `data/<short>`
  - `test/<short>`
  - `chore/<short>`
- 一个分支只做一件事；合并后删除。
- 验收/演示前由 PM 宣布冻结 `main`。

## 2. 提交

- 格式：`type(scope): subject`。
- `type`：feat / fix / docs / data / test / refactor / perf / chore。
- `scope`：data / api / frontend / match / db / infra / docs / eval。
- 正文写 why；footer 写任务或 issue：`Refs: S-08`。
- 一个 commit 只做一件事。
- 不提交：
  - `.env`、API key、数据库密码；
  - `data/raw/`、`data/interim/`、`data/processed/`；
  - 模型权重、完整摘要/全文、>10 MB 文件；
  - `__pycache__`、`.venv`、IDE 配置、临时输出。

## 3. PR 与合并

- 标题：`[S-08] 简短描述`。
- 描述写：做了什么、为什么、怎么验证、数据/接口影响。
- 至少 1 人 review；数据/API 改动建议 2 人。
- CI 必须通过；只允许 squash merge；合并后删除分支。
- 大改动拆成多个 PR；不提交不能运行的 WIP。

## 4. 数据与密钥

- 入库：`data/spec/`、`data/samples/`、`data/eval/`、`data/manifests/`。
- 不入库：`data/raw/`、`data/interim/`、`data/processed/`、向量文件、模型权重。
- 公开仓库的样例摘要正文 ≤600 字符（截断时加省略号）；完整摘要/全文只放本地或私有存储。
- 模拟需求/企业必须 `is_simulated=true`；企业用化名；不存联系人。
- API key/密码只放 `.env`；`.env.example` 入库；`.env` 不入库。
- 每次数据变更写 manifest：来源、数量、hash、时间、错误。
- 匹配结果绑定 `dataset_version + taxonomy_version + embedding_model_version`。

## 5. 代码质量与 CI

- Python 3.11；`ruff` + `pytest`。
- 前端 Vue 3 + TypeScript；`eslint` + `prettier` + `vue-tsc`。
- CI 至少跑：`python -m compileall -q scripts`；有代码后加 ruff/pytest/build。
- 提交前本地至少跑：

```bash
python -m compileall -q scripts
python scripts/data/validate_thin_slice.py --version v0.1-thin
```

## 6. 版本

- tag：`v0.1-thin`、`v0.1`、`v0.2`、`v1.0`。
- release notes 写：数据版本、taxonomy 版本、embedding 模型版本、已知问题。
- 不写日期和排期，只写版本内容。

## 7. 冲突处理

- 数据字段/标签以 `data/spec/data_contract_v0.1.md` 和 `taxonomy_v0.1.md` 为准。
- 接口以 API 契约为准；计划书与数据契约冲突以数据契约为准。
- 开题报告和过程稿只作历史材料，不作为数据、接口或验收指标的口径依据。
- 技术分歧先在 PR 里说清；BE2 给技术建议，PM 定范围。
- 文件冲突先 rebase/merge `main`，在 PR 里解决，不覆盖他人改动。

## 8. 本地材料与文档目录

- `docs/09-项目管理/` 中的规范、分工和交接文档随仓库提交；任务单、个人分工底稿、报告素材等含个人信息或一次性材料，入库前先脱敏，不能脱敏的放本地。
- 远程仓库包含项目代码、`data/` 的可入库子集、`scripts/`，以及 `docs/` 下的课程材料与参考样板；`data/raw/`、`data/processed/`、模型权重和含个人联系方式的材料不入库。
- 公开仓库中的样板/课程材料如含组员姓名，建议将仓库转为私有；仅加入 `.gitignore` 不会清除已提交历史。
