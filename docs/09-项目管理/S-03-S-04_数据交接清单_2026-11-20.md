## 1. `achievements_labeled_v0.1.jsonl`

**300 行，一行一个成果。**

```json
{
  "achievement_id": "ach_openalex_W4210818813",
  "tags": [
    {
      "dimension": "tech_field",
      "code": "electrolyte",
      "is_primary": true,
      "confidence": 0.92,
      "evidence": "sulfide solid electrolyte with high ionic conductivity",
      "method": "llm",
      "model": "qwen3.8-flash",
      "prompt_version": "v1",
      "review_status": "pending"
    }
  ],
  "extraction": {
    "material_system": "硫化物固态电解质",
    "key_metrics": [{"name": "离子电导率", "value": 12, "unit": "mS/cm", "evidence": "12 mS cm-1 at 25 C"}],
    "process": ["球磨", "退火"],
    "trl": 4,
    "trl_confidence": 0.8,
    "trl_evidence": "assembled coin cell tested at laboratory scale",
    "ip_status": "unknown"
  },
  "model": "qwen3.8-flash",
  "prompt_version": "v1",
  "review_status": "pending"
}
```

规则：

- `tags` 数组：每个成果 **1—2 个 `tech_field`**，其中**恰好 1 个 `is_primary=true`**；最多 2 个 `tech_field`。
- `dimension` 只能是 `tech_field` / `application_scenario` / `cooperation_mode`；`code` 必须在 `taxonomy_v0.1.md` 对应维度的枚举里。
- 易错 code：应用场景是 `ev_power` 不是 `ev`，`grid_storage` 不是 `storage`；拿不准查 taxonomy，不要造词。
- `confidence` 0—1；没有依据时 `≤0.4`。`cooperation_mode` 视为潜在模式，confidence 建议 `≤0.5`。`evidence` 放原文片段，不要编造。
- `review_status` 可用 `pending` / `approved` / `rejected` / `needs_review`；无证据或不确定时用 `needs_review`，记录仍会入库，不要因此丢弃。
- `extraction` 可以是 `null`；`trl` 是 1—9 整数或 `null`，**非 null 必须有 `trl_evidence`**。
- `ip_status` 只能是 `granted` / `pending` / `published` / `unknown`；论文默认 `unknown`。
- `key_metrics` 是数组，每个元素至少有 `name`；`process` 是字符串数组。
- `tag_id` / `extraction_id` 如果你已生成，请保留：必须全局唯一、跨次运行稳定；不填则导入器按 `tag_{achievement_id}_{dimension}_{code}` / `ext_{achievement_id}` 生成。

覆盖目标：**≥285/300 有主 `tech_field`（≥95%）**；**所有非空 `trl` 都有证据（100%）**。

## 2. `capability_profiles_v0.1.jsonl`

**300 行，一行一个成果。**

```json
{"achievement_id":"ach_openalex_W4210818813","language":"zh","text":"该工作围绕硫化物固态电解质展开……","method":"llm","model":"qwen3.8-flash","prompt_version":"v1"}
```

规则：

- `language` **必须显式写 `"zh"`**；本冲刺只做中文，不要写 `zh-CN` 或省略。
- `text` 150—250 字，面向产业语言的技术能力摘要，不是逐字翻译。
- `text_hash` 可省略；导入器一律用 `llm_client.text_hash(text)` 重算。如果你要填，必须用同一个函数。
- `text_id` 如果你已生成，请保留（全局唯一、跨次运行稳定）；不填则导入器按契约 4.3 生成。`text_type` 仍由导入器按 `language` 决定，不用填。
- 覆盖目标：**300/300**；确实无法产出的记录不要编造，交付时说明缺哪几条。

## 3. `embeddings_v0.1.jsonl`

**400 行 = 300 条成果 `capability_profile` + 100 条需求 `need_profile`。**

```json
{"embedding_id":"emb_ach_W4210818813_cap","object_type":"achievement","object_id":"ach_openalex_W4210818813","text_type":"capability_profile","model":"qwen3.7-text-embedding-flash","dim":1024,"text_hash":"<64 位 sha256>","vector":[0.001,0.002,...],"dataset_version":"v0.1"}
```

规则：

- `embedding_id` 全局唯一；建议 `emb_ach_<成果ID>_cap`、`emb_dem_<需求ID>_need`。
- `object_type` 只能是 `achievement` 或 `demand`；`text_type` 对应 `capability_profile` / `need_profile`。
- `object_id` 必须存在；一个对象同一个 `text_type` **只能有一条**向量。
- `model` 填 `qwen3.7-text-embedding-flash`；版本串 `qwen3.7-text-embedding-flash-1024-v1` 由我在导入时用 `--embedding-model-version` 记录，不用写进 `model`。
- `dim` 固定 **1024**；`vector` 是 1024 个有限浮点数（不能有 `NaN` / `Infinity`）。
- `text_hash` 必须等于 `llm_client.text_hash(画像文本)`；**画像文本改一个字，向量就要重算**，否则 `embedding_text_hash_mismatch` 不过。
- `dataset_version` 必须写 **`v0.1`**；写 `v0.1-thin` 会被导入器直接拒绝。
- 检索 query 的向量不用入库，评测时现算（口径文档方案 A）。
- 覆盖目标：**至少 400 条**（300 成果 + 100 需求）；额外 `title` / `abstract` 向量可加，但不能替代画像向量。

## 4. 评测标注

### 4.1 检索 query：`retrieval_queries_v0.1.csv`

20 条，每条 20 个候选，**不要改 `candidate_achievement_ids`**。填三列：

| 列 | 怎么填 |
| --- | --- |
| `relevant_achievement_ids` | 相关成果 ID，分号分隔；没有就留空 |
| `relevance_grades` | `id:2;id:1`，2=强相关、1=弱相关；只填候选集里的 ID |
| `annotator` | 你的名字/缩写 |

候选的标题和摘要去 `data/processed/achievements_clean_v0.1.jsonl`（300 条）里查，不要用薄切片的 100 条，否则 59/96 的候选查不到。

### 4.2 pair：`pair_labels_v0.1.csv`

50 对（40 同领域 + 10 跨领域），填四列：

| 列 | 怎么填 |
| --- | --- |
| `relevance_grade` | 0 / 1 / 2 |
| `rationale` | 一句话理由，指出技术领域/场景/TRL/合作模式是否兼容 |
| `annotator` | 你的名字/缩写 |
| `adjudication` | 20% 双标时由第二人填；建议 4 条 query + 10 对 pair |

口径：只看技术内容，不看作者/机构/期刊/引用数；模拟需求按正常需求处理，不因“模拟”降分；不要因为标题相似就标相关。

`load_db` 的 `--queries` / `--pairs` 直接接受 CSV 或 JSONL；CSV 的 `candidate_achievement_ids` 用分号分隔，pair 的 `relevance_grade` 会转成整数。如果直接填 JSONL，保持 `candidate_achievement_ids` 为数组、`relevance_grades` 为对象或分号串。

## 8. 常见退回原因

- `code` 不在 taxonomy：`ev`、`storage`、`separator_material` 这类简写。
- 同一成果 0 个或多个 `is_primary=true`。
- `trl` 非空但没有 `trl_evidence`。
- 画像 `language` 漏写或写成 `zh-CN`。
- 向量 `dataset_version` 写成 `v0.1-thin`。
- 画像改过但向量没重算，`text_hash` 对不上。
- 同一对象同一 `text_type` 给了两条向量。
- 评测改了候选集或成果/需求 ID。
- 不要因为没法确定就删记录：`trl=null`、`key_metrics=[]`、画像缺失都可以交，标 `needs_review` 即可；被丢弃的记录才是真的缺口。

有不确定的字段先问我，不要自己加列；要加字段我先改表和校验，再收文件。
