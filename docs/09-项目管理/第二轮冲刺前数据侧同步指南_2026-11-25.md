## 3. 按角色同步

### S-10 陈镇灏：发布触发的双向匹配引擎（优先、完整同步）

S-10 的任务不是只做离线 pair 评分，而是实现**发布触发的真实匹配任务**：

- 发布成果/需求 → 创建 `pipeline_run(stage=match)` / Celery 任务 → 对新对象与全量异侧对象做 B2 → 结果写入 `match_score`
- 同一 pair 只写一条记录，`match_id = match_{demand_id}_{achievement_id}`；两端共用，重复执行幂等
- 从数据池选择的演示记录复用已有标签/画像/向量；本轮只允许绑定现有记录，不允许改技术文本或新建 ID
- 不写死匹配结果，不修改 v0.1.2 processed，不写验收库

数据口径：

- 使用 `achievements_labeled_v0.1.2.jsonl`、`capability_profiles_v0.1.2.jsonl`、`embeddings_v0.1.2.jsonl`、`data/eval/*v0.1.2*`
- 正式 B2 仍用 **primary `tech_field` 硬过滤**：
  - 正式 B2：`0.887 / 0.730 / 0.832 / 0.912`（Recall@10 / Precision@5 / nDCG@10 / MRR）
  - B2-any 只是补充敏感性：`0.911 / 0.760 / 0.860 / 0.912`，不能当正式口径
- 场景标签减少 458 条，`reason`、风险、证据和场景匹配都要按新数据重做
- 50 对人工 pair 只做测试集，不能参与训练或调参
- **11/27 前**先交 20 条样例匹配结果，供 S-11/S-12/S-14 解阻塞
