## 0. 结论先行

1. 百炼 API key 已验证可用：对话、1024 维 embedding、rerank、JSON 模式都通过（见第 1 节）。
2. **key 只放本地 `.env`，不入库、不进文档、不发公开群**；每人使用自己的百炼 key，不共用；仓库里的 `.env.example` 只放占位符。
3. 本冲刺采用 **“统一配置契约 + 每人本地一致的 Docker 环境”**：不依赖某台机器常开，也不会因为一个人掉线阻塞全组。
4. 全组统一使用 `qwen3.7-text-embedding-flash` 1024 维；**文档用 `text_type=document`，查询用 `text_type=query`**，不得混用其他模型或维度。
5. 数据库统一为 **PostgreSQL 16 + pgvector 0.8.x**，用仓库根目录 `docker-compose.yml` 一键起本地实例。
6. 每人开工前跑 `python scripts/env_check.py`；全 PASS 才算环境就绪，输出留作验收证据。

## 2. 密钥怎么共享

### 2.1 原则

- 仓库是**公开**仓库：`.env`、API key、数据库密码一律不入库。
- key 不写进 Markdown、PPT、截图、PR 描述、CI 日志、群公告。
- `.env.example` 入库；`.env` 只存在各人本地。
- 本方案文档只写 key 前缀和用途，不写完整 key。

### 2.2 分发方式（已定：每人独立 key）

- **2026-11-19 PM 已为每位组员创建独立百炼 API key。**
- 每人只把自己的 key 写入本地 `.env`，不共用 PM 的 key，也不要把别人的 key 写进仓库、文档或群公告。
- PM 通过私密渠道单独发送；发送后按 §2.4 清单跟踪。
- 仓库的 GitHub Actions Secret 只用于 CI；默认 CI 不调用付费 API，避免误跑产生费用。
- 如果后续需要共享服务账号，再评审子 key / LLM 网关方案；本冲刺不做。

### 2.3 轮换与泄露处理

- 本 key 已在本地 `.env` 中使用；如果这段对话记录会被转发、录屏或投屏，建议在百炼控制台**轮换一次**，把新 key 写入 `.env`。
- 任何成员疑似泄露：立即在控制台禁用/轮换，PM 通知全组更新 `.env`，并检查用量。
- 在百炼控制台设置**预算/用量告警**；每周由 PM 看一次用量。

### 2.4 分发与自检清单

- [ ] 每位组员收到自己的 key（私密渠道，单独发送）
- [ ] 组员复制 `.env.example` 为 `.env`，只填自己的 key
- [ ] `pip install -r requirements.txt`
- [ ] `docker compose up -d db`
- [ ] `python scripts/env_check.py` 全 PASS
- [ ] 把 PASS 输出回报 PM

## 3. 统一环境包含什么

### 3.1 固定版本契约

| 项 | 统一值 | 说明 |
| --- | --- | --- |
| Python | 3.11 | 与计划书一致 |
| PostgreSQL | 16 | Docker 镜像 `pgvector/pgvector:pg16` |
| pgvector | 0.8.x | 镜像自带；`CREATE EXTENSION vector` |
| 对话/抽取模型 | `qwen3.8-flash` | 抽取时开 JSON 模式，关闭 thinking 省钱 |
| Embedding | `qwen3.7-text-embedding-flash` | 1024 维 |
| `embedding_model_version` | `qwen3.7-text-embedding-flash-1024-v1` | 入库/匹配结果必须带 |
| Rerank（B3 用） | `qwen3.7-text-rerank` | 本冲刺不阻塞 |
| 向量维度 | 1024 | `vector(1024)`，不得 768/1024 混用 |

### 3.2 环境变量

以 `.env.example` 为准，核心变量：

```text
DASHSCOPE_API_KEY            每人自己的百炼 key（只放本地 .env）
DASHSCOPE_BASE_URL           https://dashscope.aliyuncs.com/compatible-mode/v1
QWEN_CHAT_MODEL              qwen3.8-flash
QWEN_EXTRACT_MODEL           qwen3.8-flash
EMBEDDING_MODEL              qwen3.7-text-embedding-flash
EMBEDDING_DIM                1024
EMBEDDING_MODEL_VERSION      qwen3.7-text-embedding-flash-1024-v1
RERANK_MODEL                 qwen3.7-text-rerank
DATABASE_URL                 postgresql://aim:...@127.0.0.1:5432/academia_industry_match
OPENALEX_MAILTO              可选，填团队邮箱可提高 OpenAlex 配额
```

### 3.3 Embedding 调用约定（重要）

- 成果、需求、画像等**入库文本**：`text_type="document"`。
- 检索 query：`text_type="query"`。
- 同一批文本必须用同一模型、同一维度、同一 `text_type` 规则；换模型/换文本必须重算。
- 每条向量记录 `model`、`dim`、`text_hash`、`embedding_model_version`。
- 批量建议 10—25 条/请求；按 `text_hash` 缓存，避免重复计费。
- 本冲刺统一用 Qwen；BGE-M3 只作为文档备选，**不要**一部分人用 BGE、一部分人用 Qwen。

### 3.4 数据库

- 本地一键启动：`docker compose up -d db`。
- 首次初始化自动执行 `db/init/00_extensions.sql`，安装 `vector` 扩展。
- 表结构、索引、迁移由 BE2（张小桐）在 `migrations/` 维护；`vector(1024)`。
- 开发库连接：`postgresql://aim:<本地 .env 中的密码>@127.0.0.1:5432/academia_industry_match`（密码只在本地 `.env`，共享环境请更换）。
- 如果 5432 被占用，在 `.env` 改 `POSTGRES_PORT=5433`，同时改 `DATABASE_URL`。

### 3.5 共享数据库的演进

| 阶段 | 做法 | 原因 |
| --- | --- | --- |
| 本冲刺（现在） | 每人本地 Docker，同一 compose + 同一迁移 | 零成本、可复现、不互相阻塞 |
| API/前端联调前 | 起一台集中式 PostgreSQL（云主机/学院服务器），迁移同一套 `migrations/` | 让 BE1/FE 看到同一份数据 |
| 可选增强 | 集中式 LLM/Embedding 网关（如 LiteLLM），成员用虚拟 key | key 不落地到每人机器，能统计用量；本冲刺不做 |

集中式数据库要求：

- 不对公网开放 5432；用安全组/白名单/VPN/SSH 隧道。
- 分角色账号：`aim_owner`（迁移）、`aim_writer`（导入）、`aim_reader`（API/前端只读）。
- 每日 `pg_dump` 备份；导入仍走 `load_db.py`，保证可重建。

### 3.6 共享 API 客户端

`scripts/common/llm_client.py` 统一封装，避免每个人重写 HTTP 调用：

```python
from scripts.common.llm_client import chat_json, embed_texts, rerank

labels = chat_json(messages, model="qwen3.8-flash")       # JSON 模式 + 自动重试
vectors = embed_texts(texts, text_type="document")        # 批量 + text_hash 缓存
hits = rerank(query, documents, top_n=10)                 # B3 精排（后续）
```

- 自动读取 `.env`，不硬编码 key；使用各自的本机 key。
- `embed_texts` 按 `(model, dim, text_type, text_hash)` 缓存到 `data/interim/embedding_cache.jsonl`（不入库）。
- 每次调用写 `data/interim/api_usage.jsonl`（不入库），包含耗时、token、request_id；评测报告可汇总。
- `python scripts/common/llm_client.py --check` 只看配置；`--demo` 跑小样本；`--clear-cache` 清缓存。
- 单元测试：`python -m unittest discover -s tests -t . -v`（不联网）。

### 5.1 国内网络拉不到镜像时

Docker Hub 直连可能超时。Docker Desktop 已配置镜像加速仍失败时，可显式从镜像站拉取再打回本地 tag：

```bash
docker pull docker.1panel.live/pgvector/pgvector:pg16
docker tag docker.1panel.live/pgvector/pgvector:pg16 pgvector/pgvector:pg16
docker compose up -d db
```

也可把 `docker.m.daocloud.io` 等其他可用镜像站按同样方式使用。镜像站可用性会变化，失败时换一个源即可；不要修改 `docker-compose.yml` 里的标准镜像名。

如果**宿主机能访问镜像站、但 Docker daemon 卡在 “Pulling fs layer”**，通常是 Docker Desktop 的代理链路问题。可在宿主机通过 registry HTTP API 下载镜像层并组装 `docker load` 的 tar，或把镜像站域名加入 Docker Desktop 的代理绕过列表后重启 Docker；也可以继续用下面的离线包方式。

如果所有镜像站都不通，可由一台能拉取的机器导出离线镜像，再传给其他人：

```bash
# 在能联网的机器上
docker pull pgvector/pgvector:pg16
docker save pgvector/pgvector:pg16 -o pgvector-pg16.tar

# 在目标机器上（把 tar 传过去）
docker load -i pgvector-pg16.tar
docker compose up -d db
```

## 7. 费用与调用纪律

- 抽取先跑 30 条校准，确认 Prompt 和 JSON 通过后再全量；不要反复全量重跑。
- 对话默认 `enable_thinking=false`；抽取输出用 JSON 模式；设置合理 `max_tokens`。
- Embedding 按 `text_hash` 缓存；批量 10—25 条；不要逐条调用。
- 记录每次批量调用的 usage（tokens/条数/耗时），写入 manifest，作为评测报告的开销数据。
- 在百炼控制台设置预算/告警；异常用量先停再查。
- 该 key 还能调用 `qwen4-max`、`deepseek-v4-pro` 等高价模型；**只允许使用本方案约定的 `qwen3.8-flash` / `qwen3.7-text-embedding-flash` / `qwen3.7-text-rerank`**。若控制台支持子 key 或模型白名单，优先启用。

## 8. 本冲刺不做

- 不做集中式 LLM 网关；不把 key 放在共享服务器上。
- 不做公网数据库；不把 5432 暴露到公网。
- 不做自动密钥轮换；不把真实 key 写进 CI 日志。
- 不引入 BGE-M3 本地推理（无 GPU 时性价比低），避免与 Qwen 向量混用。
