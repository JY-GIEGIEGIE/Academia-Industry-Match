# 标签与画像文件的输入格式（2026-11-19）

> 适用：`achievements_labeled_v0.1*.jsonl`、`capability_profiles_v0.1*.jsonl`
> 依据：`data/spec/data_contract_v0.1.md` 第 4.3、4.4、4.5 节
> 作者：张小桐（BE2）｜请陈镇灏（AI）按此产出，导入侧按此解析

## 1. 两个文件的关系

| 文件 | 每行内容 | 落库表 |
| --- | --- | --- |
| `achievements_labeled_v0.1-thin.jsonl` | 一个成果 + 它的标签数组 + 抽取结果 | `achievement_tag`、`achievement_extraction` |
| `capability_profiles_v0.1-thin.jsonl` | 一个成果的能力画像文本 | `achievement_text` |

`achievement_id` 必须与 `achievements_clean_v0.1-thin.jsonl` 一致，否则导入报错。

## 2. `achievements_labeled_v0.1-thin.jsonl`

一行一个成果：

```json
{
  "achievement_id": "ach_openalex_W4210818813",
  "tags": [
    {
      "dimension": "tech_field",
      "code": "electrolyte",
      "is_primary": true,
      "confidence": 0.92,
      "evidence": "sulfide solid electrolyte with high ionic conductivity",
      "method": "llm",
      "model": "qwen3.8-flash",
      "prompt_version": "v1",
      "review_status": "pending"
    },
    {
      "dimension": "application_scenario",
      "code": "ev_power",
      "is_primary": false,
      "confidence": 0.7,
      "evidence": "for electric vehicle applications",
      "method": "llm",
      "model": "qwen3.8-flash",
      "prompt_version": "v1",
      "review_status": "pending"
    }
  ],
  "extraction": {
    "material_system": "硫化物固态电解质",
    "key_metrics": [{"name": "离子电导率", "value": 12, "unit": "mS/cm", "evidence": "12 mS cm-1 at 25 C"}],
    "process": ["球磨", "退火"],
    "trl": 4,
    "trl_confidence": 0.8,
    "trl_evidence": "assembled coin cell tested at laboratory scale",
    "ip_status": "unknown"
  },
  "extraction_run_id": "extract-20261120T101500Z",
  "model": "qwen3.8-flash",
  "prompt_version": "v1",
  "review_status": "pending"
}
```

规则：

- `tags` 可以是空数组（该成果没抽到标签），但覆盖率统计会单独报。
- `extraction` 可以是 `null`（该成果跳过抽取）。
- `tag_id`、`extraction_id` 如果你已生成，请保留（必须全局唯一、跨次运行稳定）；不填则导入器按 `tag_{achievement_id}_{dimension}_{code}`、`ext_{achievement_id}` 生成。
- `dimension` 只能是 `tech_field`、`application_scenario`、`cooperation_mode`；`code` 必须在 `taxonomy_v0.1.md` 对应维度的枚举里。易错点：应用场景里写 `ev_power` 而不是 `ev`，`grid_storage` 而不是 `storage`；拿不准就查 taxonomy 的表格，不要自己造词。
- `tech_field` 每个成果**恰好 1 个** `is_primary=true`，最多 2 个 `tech_field`。
- `trl` 为 1—9 的整数或 `null`；非 `null` 时必须给 `trl_evidence`。
- 没有依据时 `confidence ≤ 0.4`，`review_status` 写 `needs_review`（标签/抽取表已允许该值，记录仍会入库）；证据放原文片段，不要编造。
- `ip_status` 只能是 `granted`、`pending`、`published`、`unknown`；论文默认 `unknown`。

## 3. `capability_profiles_v0.1-thin.jsonl`

一行一个成果：

```json
{"achievement_id": "ach_openalex_W4210818813", "language": "zh", "text": "该工作围绕硫化物固态电解质展开，通过组分调控与界面包覆改善离子传输效率，在实验室规模完成扣式电芯验证，循环稳定性与倍率性能均优于同类体系。研究进一步明确了硫化物与锂金属界面的副反应机理，并给出可放大的干法成膜工艺参数，包括球磨时间、退火温度与压制压力。相关制备路线具备向中试放大的潜力，可用于动力电池与储能场景的技术合作，尤其在快充与高能量密度方向具有工程价值。", "text_hash": "<可选，导入器会补算>", "method": "llm", "model": "qwen3.8-flash", "prompt_version": "v1"}
```

规则：

- `language` 只能是 `zh` 或 `en`，**必须显式写**。省略时导入器按 `zh` 处理，英文画像若漏写会被存成 `capability_profile_zh`，导致中英两类文本混在一个枚举值里；所以英文一律写 `"en"`。本冲刺只做 `zh`。
- `text_type` **由导入器按语言决定**（`capability_profile_zh` / `capability_profile_en`），你不用填。`text_id` 如果你已生成，请保留（全局唯一、跨次运行稳定）；不填则按契约 4.3 的公式 `txt_{achievement_id}_{text_type}_{lang}` 生成，实际形如 `txt_ach_openalex_W4210818813_capability_profile_zh_zh`。尾部会出现两个 `zh`，因为 `text_type` 本身已含语言、公式又加了一次，这是契约规定的写法，照此执行即可（若觉得冗余，需要三人同意后改契约，不要在数据里自行简化）。
- `text_hash` 可省略。导入器**一律**用 `scripts/common/llm_client.py` 的 `text_hash(text)` 重新计算；如果你提供了值且与计算结果不同，会提示不一致并以重算值为准。所以这一列可以完全不填，只要向量侧也用同一个函数的输出，两边 hash 就能对上。
- 画像长度 150—250 字，不是逐字翻译，是面向产业语言的技术能力摘要。

## 4. 导入命令

全量（主库，当前 300 条 `v0.1`）：

```bash
python scripts/data/load_db.py --dsn "$DATABASE_URL" \
  --dataset-version v0.1 \
  --embedding-model-version qwen3.7-text-embedding-flash-1024-v1 \
  --labeled data/processed/achievements_labeled_v0.1.jsonl \
  --profiles data/processed/capability_profiles_v0.1.jsonl
```

薄切片（独立的薄切片库，不能指向全量库）：

```bash
python scripts/data/load_db.py --dsn "$THIN_DSN" \
  --dataset-version v0.1-thin \
  --embedding-model-version qwen3.7-text-embedding-flash-1024-v1 \
  --labeled data/processed/achievements_labeled_v0.1-thin.jsonl \
  --profiles data/processed/capability_profiles_v0.1-thin.jsonl
```

`--dataset-version` 必须与行内版本一致，导入器会拒绝混版本写入；从薄切片升级到全量加 `--allow-mixed-versions`。

`--check` 也会校验这两个文件（存在时），不连库。缺文件不报错，只在覆盖率检查里体现。
