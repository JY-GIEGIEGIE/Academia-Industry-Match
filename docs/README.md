## 五、使用建议

1. **先读评分细则**：每份报告的形式分（30 分）和内容分（70 分）都有明确子项，先按细则列提纲，再写内容。
2. **以定稿为范围基线**：项目范围、进度、交付物以 `03-项目计划/G04_项目计划书_10月25日定稿` 为准；技术栈与数据口径以 `数据口径更正记录_v0.1.md` 和 `data/spec/` 为准；过程稿只用于追溯细节。
3. **保持编号对应**：需求规格书中的需求编号、设计报告中的模块编号、测试报告中的用例编号要能互相对应，这是终期综合评价的核对点。
4. **保留证据**：会议纪要、评审记录、测试日志、提交记录、AI 使用记录按细则要求留档；报告中的结论要能定位到证据。
5. **AI 使用说明**：细则要求说明工具、用途、人工核验责任人和核验方式；AI 生成的测试用例必须实际执行并记录真实结果。
6. **提交格式**：按细则提交可复制文字的 PDF，同时保留可编辑源文件；文件命名采用「组号_材料名称_版本.pdf」。

## 七、统一口径（2026-11-18）

以下口径已经确定。开题报告、过程稿和 PRD 中与之不一致的表述按历史材料处理，不再作为后续文档依据。

1. **技术栈与数据**：Python 3.11、PostgreSQL 16 + pgvector 0.8.x、BGE-M3 1024 维（备选 Qwen 1024 维）；OpenAlex 为主源，CNKI/万方不抓取；需求/企业为模拟数据。以 `03-项目计划/数据口径更正记录_v0.1.md`、`data/spec/data_contract_v0.1.md` 和 `data/spec/taxonomy_v0.1.md` 为准。
2. **质量指标**：单元测试覆盖率按关键模块 ≥60% 验收，全项目不设 80% 硬指标；检索评测按 `data/spec/eval_spec_v0.1.md`：Recall@10 ≥0.70、Precision@5 ≥0.70。
3. **匹配时延**：匹配是离线 pipeline，不设 2 秒在线响应指标；如后续实现在线查询接口，只对该接口单独约定时延。
4. **交付物与风险表**：课程交付物以 `05-课程要求/课程报告与评分细则.md` 为准；后期报告补齐需求规格书、设计报告、测试报告的提交节点，风险表按细则 C6 补触发条件和负责人。定稿计划书的 D1—D8 只作历史范围参考。
